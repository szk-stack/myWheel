# myWheel

一个**零框架**的极简 Agent：agent 循环、工具系统、插件机制、事件日志全部从零手写，
后端只用 Python 标准库，不套 LangChain 那类框架——**因为目的是看清楚每一步到底发生了什么**。

> 名字是"我的轮子"：做这个项目本身就是在重复造轮子。
> 造轮子不为替代谁，只为在造的过程中搞明白它到底怎么转。

（前端有一个辅助文件 `static/marked.umd.js`——把 AI 回复渲染成 Markdown 格式的开源库，已下载到项目里，运行时不需要联网安装任何东西。）

**它能做什么**

- 前端：一个网页（`static/index.html`），流式打字机输出
- 后端：纯 Python 标准库，装了 Python 就能跑
- 大模型：DeepSeek（任何 OpenAI 兼容的接口都可以换）
- 架构：**空槽 + 插件**，以后加功能就往 `plugins/` 里扔文件
- 数据：**事件日志**（`data.jsonl`，只追加不重写）——思路学自开源项目 Pi
- 工具：模型能自己读写文件、跑命令、截图自检，多轮循环直到收工
- 子代理：主 agent 能"派小弟去干活"——独立上下文、只带回结论
- 图片 / 截图理解：Ctrl+V 粘贴截图或点「图片」上传，自动切换视觉模型
- 知识库：**RAG 检索**（BM25 + 向量 + RRF 融合），模型能查自己的文档

> 📚 想深入原理、改造代码？技术文档在 [`docs/`](docs/README.md)（架构总览 + 模块文档）。
> 🧪 知识库那一套的选型权衡和实测数据，见 [`docs/design/rag-plan-2026-10.md`](docs/design/rag-plan-2026-10.md)。

## 一、跑起来（一共 3 步）

### 第 1 步：填 API Key
打开 `config.py`，把这一行改成你的 Key（保存在引号里）：

    API_KEY = "sk-你的key"

Key 在 https://platform.deepseek.com 创建，以 `sk-` 开头。

### 第 2 步：启动后端
在本文件夹里打开终端，运行：

    python server.py

看到 "服务已启动" 几个字就成功了。

### 第 3 步：打开网页
浏览器访问 http://localhost:8000 ，开聊！

> 注意：改了 `config.py`（比如填了 Key）之后，要**重启服务**才生效：
> 在终端按 Ctrl+C 停掉，再重新运行 `python server.py`。

### 可选：开启知识库（让模型能查文档）

上面三步跑完就已经能用了。想要"模型能查项目文档"再往下走：

```bash
python -m pip install numpy jieba     # 只有知识库需要，核心功能不依赖
python rag.py build                   # 建关键词索引（不联网，秒级）
```

然后在 `config.py` 里填 `DASHSCOPE_API_KEY`（阿里云百炼，[开通地址](https://bailian.console.aliyun.com)，
免费额度足够），再建向量索引：

```bash
python kb_vector.py build             # 调接口，283 块约 16 秒、4 分钱
```

> ⚠️ **装包请用 `python -m pip`，不要直接用 `pip`**——电脑上装过多套 Python 时，
> 两者可能指向不同环境，`pip install` 完 `import` 却找不到，就是踩了这个坑。

## 二、每个文件是干嘛的

| 文件 | 作用 | 要动它吗 |
|---|---|---|
| `config.py` | 所有配置（Key、模型、人设、端口） | ★ 常改 |
| `server.py` | 启动入口，收发 HTTP 请求 | 基本不动 |
| `engine.py` | 引擎：把流程串起来 | 基本不动 |
| `llm.py` | 和 DeepSeek 说话 | 基本不动 |
| `hooks.py` | 空槽机制（核心就是几个列表） | 想加新槽时才动 |
| `storage.py` | 事件日志管理员：追加事件 + 回放推导状态 | 想换存储方式时动 |
| `toolbox.py` | 工具箱：注册表 + 调度 + 自动加载 tools/ | 基本不动 |
| `tools/` | ★ 工具目录：模型能用的"能力"都放这 | ★ 常加 |
| `plugins/` | ★ 插件目录，以后的功能都放这 | ★ 常加 |
| `static/index.html` | 聊天网页（含前端的全部逻辑） | 想改界面时动 |
| `data.jsonl` | 事件日志：发生过的一切都记在这（自动生成） | 可以打开看 |
| `data.json.bak` | 老格式数据的备份（第一次"搬家"后自动留下） | 不用管 |

## 三、一次对话都发生了什么

    浏览器（保存全部会话 + 当前会话的完整历史）
       │  POST /api/chat/stream，带上当前会话的全部历史
       ▼
    server.py   收请求，开一条"流式通道"（SSE）
       ▼
    engine.py   跑一轮"agent 循环"：
       ├─ ① before_llm 空槽 → system_prompt 插件插入人设
       ├─ ② 流式调用 DeepSeek：
       │       ├─ 模型直接回答 → 文字一段段流给浏览器（打字机效果）
       │       └─ 模型要求用工具 → 执行工具 → 结果塞回历史 → 再调模型（循环）
       └─ ③ after_llm 空槽 → logger 插件打印日志
       ▼
    浏览器边收边显示

    另外：页面上的每个动作（发消息、新建、删除、重命名、切换、工具调用）
    都会被翻译成一条条"事件"，追加到 data.jsonl 日志的末尾——
    只往后加行，从不重写文件。

## 四、对话数据存在哪？（事件日志，学自 Pi）

数据存在 `data.jsonl` 里。"jsonl" 的意思是**每行一条 JSON 记录**，
用记事本打开长这样（真实例子）：

    {"type": "session", "id": "c179...", "title": "新对话", "timestamp": "..."}
    {"type": "message", "conversation_id": "c179...", "role": "user", "content": "你好", "timestamp": "..."}
    {"type": "message", "conversation_id": "c179...", "role": "assistant", "content": "你好呀！", "timestamp": "..."}
    {"type": "rename", "id": "c179...", "title": "打个招呼", "timestamp": "..."}

全部事件类型（`type` 字段）：

| type | 含义 |
|---|---|
| `session` | 新建了一个会话 |
| `message` | 一条新消息（role 是 user 或 assistant） |
| `tool` | 一次工具调用记录（调了什么、结果如何——方便回溯；可能带"附加数据"，比如子代理的完整过程） |
| `rename` | 会话改名 |
| `delete` | 删除会话（日志里的旧消息仍在，只是回放时忽略它） |
| `switch` | 切换当前打开的会话 |

**关键思想："当前数据"是算出来的，不是存的。**
每次打开页面，后端会从头到尾把日志**回放**一遍
（遇到 session 就新建、message 就追加、delete 就忽略……），
推导出会话列表再发给页面。这就是 Pi（github.com/earendil-works/pi）
的核心思路：**日志是唯一真相，状态只是它的投影**。

好处：写入快（只加一行）、不怕写坏（顶多丢最后一行）、历史完整可追溯。

## 五、工具调用（模型自己能干活了）

模型现在会自己调用这些工具干活：

| 工具 | 作用 |
|---|---|
| `list_dir` | 列出目录里的文件 |
| `read_file` | 读文件（带行号，可用 offset/limit 分段读）|
| `write_file` | 创建 / 整体覆盖文件 |
| `edit_file` | 精确修改文件（要求原文唯一出现，防止改错地方）|
| `exec_command` | 在工作区里执行系统命令（跑脚本、git、查环境）|
| `screenshot` | 用 Edge 无头模式给网页截图（存工作区的 `.screenshots/`）|
| `view_image` | 读取工作区里的一张图片"看"一眼（多模态）|
| `spawn_agent` | 派一个子代理独立干活（详见下方"子代理"小节）|
| `search_kb` | 在知识库里检索文档（详见下方"知识库"一节）|

对话时它可能连续调用好几个（先列目录 → 再读文件 → 再回答你），
这叫作 **agent 循环**：调模型 → 要工具就执行 → 结果塞回去 → 再调模型。
**默认不限制轮数**（`config.py` 的 `MAX_TOOL_ROUNDS = 0`）——和 Pi / dsh 一样，
让模型自己决定什么时候收工；想加保险就填个正数。
随时想叫停：点输入框右边的「**停止**」按钮（生成中「发送」会变成红色「停止」，
点了立刻断，不用关页面）。

- **安全边界**：文件操作都被"关"在工作区里（挡住 `../` 越界）；
  **注意 `exec_command` 是例外**——命令可以是任意程序，工作区只是它的默认执行目录，
  技术上没法限制它"只动工作区"（危险命令有黑名单兜底，但那是防手滑、不是保险箱）；
- **一键关闭**：`config.py` 里 `ENABLE_TOOLS = False` 可以关掉全部工具；
- **工具记录**：每次工具调用都会变成对话里的一张灰色小卡片（点开看详情），
  也写进 `data.jsonl` 日志（`tool` 事件）——随时可以回溯"它当时干了什么"。

**怎么加一个新工具**：往 `tools/` 里扔一个文件，照着 `list_dir.py` 抄三段
（说明书 → 执行函数 → register 登记），重启服务就生效——和插件一样"文件即生效"。

### 子代理（spawn_agent）：让 agent"派小弟去干活"

主 agent 可以派一个**子代理**去独立完成任务：它有自己的独立上下文（看不到主对话），
能自己调用工具干活，干完只把一份精炼的结论带回来。

- 适合"要翻很多文件、但只需要结论"的调查类任务（找 TODO、统计文件、总结某个模块）；
- 中间过程的上下文消耗全部隔离在子代理里——主对话只多一条结论，窗口保持清爽
  （和上下文压缩互补：**压缩是事后收拾桌子，子代理是事前派实习生去跑腿**）；
- **防套娃**：子代理的工具箱里禁掉了 `spawn_agent` 自己（小弟不能再招小弟）；
- **继承工作区**：子代理在你当前设定的工作区里干活（它同样无权改工作区）；
- **过程可查看**：子代理的完整过程（任务 → 每次工具调用 → 结论）会随记录存进日志——
  在它的工具卡片里点「**展开子代理过程**」就能看，刷新页面后仍在；
- 总开关：`config.py` 里 `ENABLE_SUBAGENT = False` 可整体关掉；
  子代理的人设（`SUBAGENT_PROMPT`）也在 `config.py` 里，可以随便改。

### 工作区（agent 的"干活范围"）

每个对话可以有自己的**工作区**——agent 的所有文件操作都被锁在这个目录里：

- **新建对话时自动分配默认工作区**：`sandbox/<时间戳>`（如 `sandbox/2026-10-16-20-56`）——
  每个任务各有独立沙箱，agent 默认不会直接动项目文件；
- 点输入框上方的"工作区"标签可以切换：
  - **浏览选择**：弹出系统"选择文件夹"对话框，像选文件一样选目录（对话框里可"新建文件夹"）；
  - **手动输入**：输入一个纯名字（如 `练习1`）会自动在 `sandbox/练习1` 建沙箱；输入路径不存在会自动创建；留空 = 切到项目目录；
  - **项目目录**：让 agent 直接在项目里干活（改代码、整理文档等）。

安全设计的底线：**工作区只能由你设定，模型无权修改**（它没有"切换工作区"的工具）；
盘符根目录、用户主目录、系统目录会被拒绝；换工作区后 `../` 越界拦截照样生效。

### 上下文管理（自动压缩 + 用量显示）

聊得越来越久时，上下文会膨胀——系统会自动帮你"瘦身"：

- 输入框上方的计量条显示**上下文估算用量**（点开有详情），红色刻度线 = 压缩阈值的位置；
- 用量超过窗口的 **70%**（`config.py` 里可改）时自动压缩：
  把较早的对话交给模型总结成一段**摘要**，之后只发「摘要 + 最近 12 条消息」；
- 压缩**不删任何原始消息**（它们都在 `data.jsonl` 里），刷新后还能看到"已压缩"小卡片（点开读摘要）；
- 也可以随时点用量条里的「**立即压缩**」手动触发（测试效果、解压长会话都方便）。

### 链路日志（每次任务的完整执行记录）

点击左下角「**查看链路日志**」，可以看到每一次任务的完整链路：

- **每轮实际发给模型的上下文结构**（压缩、工具协议转换之后的真实形态，逐条消息可展开）；
- 模型的**思考过程**（服务端返回 reasoning 时才有——时有时无，取决于模型侧行为）；
- 每一次**工具调用**（参数、结果、耗时）；
- 模型的每轮输出、最终回答、总耗时，以及失败 / 中断状态（出错也留痕）。

数据存在 `traces.jsonl`（不进版本库）。它回答的是"这次任务到底发生了什么"——
排查"它为什么这样回答 / 为什么调了那个工具"时的第一现场。

### 图片 / 截图理解（多模态输入）

输入框左侧有「**图片**」按钮；更顺手的方式是**直接 Ctrl+V 粘贴截图**——图片会出现在
输入框上方的缩略图条里（点 × 移除），随消息一起发出去。

- **自动切换视觉模型**：带图片的请求会用 `deepseek-v4-flash-vision-exp`
  （`config.py` 的 `VISION_MODEL`），没有图片的请求仍用普通模型；
- **图片存文件，日志只存路径**：图片本体存在项目下的 `uploads/` 目录
  （不进版本库），消息里只记相对路径——所以 `data.jsonl` 不会被 base64 撑爆；
- 支持 JPEG / PNG / GIF / WebP，单张 ≤ 5 MB（`config.py` 的 `MAX_IMAGE_MB`）；
- 每张图片约算 400 token（官方单图上限约 384）；
- 总开关：`config.py` 里 `ENABLE_VISION = False` 可整体关掉图片输入。

**agent 会自己截图检查效果**：模型有两个自检工具——`screenshot`（Edge 无头截图）
和 `view_image`（把图片"看"回来）。所以让它做一个小游戏，它会：
生成页面 → **截图** → **看图** → 发现"方块颜色不对/布局溢出" → 改 → 再截，
而不是"写完就交卷"。

## 六、知识库（RAG）：让模型查自己的文档

模型可以查 `docs/` 和 `knowledge/` 里的文档，回答"这个项目是怎么实现的"这类问题，
而不是凭印象编。查完会在回答里标出来源（文件名 + 章节）。

### 它怎么工作的

    离线（建索引；改了文档要重跑）
      docs/ + knowledge/ 下的 md/txt
        → 按标题层级切成小块（默认 800 字，带 120 字重叠，代码块内不拆）
        → 两路索引：BM25 关键词倒排 + 向量矩阵

    在线（每次提问）
      问题 → 两路各召回 30 条 → RRF 融合 → 取前 5 条 → 塞进上下文

两路各自的强项正好互补：

- **BM25**（关键词）：专有名词、函数名、错误码、精确短语——搜 `ENABLE_KB` 只有它能中；
- **向量**（语义）：换个说法也能找到——搜"沙箱"能命中写着"工作区"的段落，
  搜"报错"能命中"错误翻译"；
- **RRF 融合**：只看名次不看分数。因为 BM25 分数无上界、余弦相似度在 -1~1 之间，
  直接相加等于让 BM25 单方面决定结果。

实测：283 块文档，BM25 检索 9 ms，向量检索 387 ms（其中 380 ms 是"把问题变成向量"
的那次网络请求，矩阵乘本身不到 1 毫秒）。

### 命令

| 命令 | 作用 |
|---|---|
| `python rag.py build` | 建关键词索引（不联网） |
| `python rag.py search 空槽机制` | 命令行试搜 |
| `python rag.py stats` | 看索引体检报告 |
| `python kb_vector.py build` | 建向量索引（调接口，约 4 分钱） |
| `python kb_vector.py compare 沙箱` | **三路对比**：BM25 / 向量 / 融合，并排看差在哪 |

`compare` 是最有教学价值的命令——同一个问题，三种检索的差异一目了然。

### 往知识库里放什么

`knowledge/` 下的 `.md` 和 `.txt` 会被全部索引。判断标准只有一条：
**模型本来不知道的东西才值得放。**

- 值得放：你自己的取舍判断、踩过的坑、项目的隐含约定、术语在本项目里的具体含义；
- 不值得放：抄来的教程、通用概念定义——它们"看起来都相关"，会挤占前 5 个名额，
  却答不到点上。

完整方案（逐环选型对比、实测数据、分阶段计划）见
[`docs/design/rag-plan-2026-10.md`](docs/design/rag-plan-2026-10.md)。

## 七、怎么加一个新功能（模块化插入）

1. 在 `plugins/` 里新建一个 `.py` 文件
2. 写一个函数：改一改 `ctx`，然后 `append` 到对应空槽
3. 重启服务，插件自动生效，主流程一行都不用改

比如做一个"敏感词打码"插件：

    # plugins/bad_words.py
    from hooks import after_llm

    BAD_WORDS = ["某词1", "某词2"]

    def filter_words(ctx):
        for w in BAD_WORDS:
            ctx["reply"] = ctx["reply"].replace(w, "***")

    after_llm.append(filter_words)

## 八、练习题（从易到难）

1. 改 `config.py` 里的 `SYSTEM_PROMPT`，让 AI 变成"英语老师"
2. 写一个插件（挂 `after_llm`），统计每次回答有多少个字，打印出来
3. 写一个插件（挂 `before_llm`），历史超过 10 条时只保留最近 6 条（防止超出模型的上下文长度）
4. 在左侧列表底部加一个"删除全部对话"按钮（提示：照抄 `deleteConversation` 的写法）
5. 写一个小脚本：统计 `data.jsonl` 里一共有多少条 `message` 事件、你最常用的会话是哪个（提示：逐行读、数 `type` 字段）
6. 写一个新工具扔进 `tools/`：比如 `count_lines`（数一数某个文件有多少行）（提示：照抄 `read_file.py` 的三段结构）
7. 给子代理的"过程脚印"加点花样：让报告末尾写上子代理这次花了多少秒（提示：在 `spawn_agent.py` 跑循环前记下时间，结束后算差值）

## 九、常见问题

- **提示端口被占用？** 把 `config.py` 里 `PORT = 8000` 改成 `8001`。
- **提示没有 API Key？** 检查 `config.py` 里的引号是不是真的填了内容、有没有保存。
- **改了配置没生效？** config 是启动时读取的，改完要重启服务（Ctrl+C 再运行）。
- **Key 会不会泄露？** Key 只存在你电脑的 `config.py` 和后端内存里，前端网页看不到它。
- **`data.jsonl` 可以删吗？** 可以。删掉后重新打开页面会从空白开始（文件会自动重建）。
- **`data.json.bak` 是什么？** 老格式数据的备份。程序升级后第一次运行时，会自动把旧格式"搬家"成新的事件日志（就像 Pi 升级旧会话文件一样），原来的 `data.json` 会改名成 `.bak` 留档。
- **模型怎么突然开始"翻"我的文件？** 那是它在使用工具。每次工具调用都会显示成灰色小卡片，点开能看到它到底读了/写了什么；不想要这个能力就把 `config.py` 的 `ENABLE_TOOLS` 改成 `False`。
