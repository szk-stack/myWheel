# 工具：exec_command（执行系统命令）

| 状态 | 最后更新 | 关联代码 | 代码基线 |
|---|---|---|---|
| Stable | 2026-10-24 | `tools/exec_command.py` | `180577f` |

> 所属：[工具系统总览](README.md)

## 1. 职责

在工作区目录里执行一条 **Windows 命令（cmd 语法）**，返回退出码和输出。
给 agent 补上"真正动手跑程序"的能力：运行 Python 脚本、git 操作、
查看版本 / 环境、批量处理文件等。

## 2. 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `command` | string | 是 | 完整命令（cmd 语法，如 `python xxx.py`、`git status`、`dir`） |

## 3. 行为与输出

- **工作目录 = 当前工作区**（没设工作区的会话回退到项目目录，和 `safe_path` 一致）；
- `shell=True`（Windows 上是 `cmd.exe /c`）；`stdin` 关闭——
  等待输入的命令会直接失败，而不是把对话挂死；
- **超时 60 秒**（`TIMEOUT_SECONDS`）：超时强制结束子进程；
- **输出截断 8000 字符**（`MAX_OUTPUT_CHARS`）：超出保留开头并注明原文长度；
- **编码三层兜底**：输出字节先按 UTF-8 严格解码 → 失败退回 GBK（中文 cmd 的
  系统代码页）→ 再不行 UTF-8 替换模式。保证中文输出不乱码、任何情况不崩溃；
- 输出格式：

  ```
  命令：dir
  退出码：0

  （标准输出；有报错时附 [stderr] 段）
  ```

## 4. ★ 安全边界（必读）

与文件工具不同：`exec_command` **不受工作区路径锁保护**——
命令是任意程序，`cd ..` 或绝对路径都能走。本工具的安全模型是四层：

1. **工作目录默认锁定**在工作区（只是"默认"，不是"限制"）；
2. **危险命令黑名单**（`BLOCKED_PATTERNS`）——格式化磁盘 / 关机 / 磁盘分区 /
   删整个盘 / fork bomb 直接拒绝。**这是防手滑，不是安全边界**（刻意变换写法总能绕过）；
3. **超时**（60 秒）防挂死；
4. **输出截断**防塞爆模型上下文。

要更严格的管控（命令确认 / 白名单），在 `before_tool` 空槽挂插件——
该槽的 `ctx["blocked"]` 机制就是为这类场景预留的（见
[插件系统](../plugins/README.md) §2）。

## 5. 设计决策

- **黑名单而非白名单**：白名单安全但砍能力（要的是"能跑脚本"）；
  黑名单 + 诚实披露边界，符合本项目"个人工具、用户自己看着"的定位；
- **stdin 关闭**：交互式命令（`pause`、不带 `-m` 的 `git commit`）在自动化环境里
  没人能应答——关掉比挂着等更诚实；
- **不 chcp 65001**：不改变子进程的代码页行为，而是在父进程侧做
  "UTF-8 → GBK" 解码兜底——对子进程零侵入，两种编码都能正确解；
- **stdout 与 stderr 合并返回**：模型要看到报错才能自己修（和文件工具的
  错误文本哲学一致）。

## 6. 已知限制与坑

- **路径锁管不到命令内部**（见 §4）——功能性质决定的，不是 bug；
- **编码极端情况仍可能乱**：同一段输出里混着两种编码时无法两全（罕见）；
- **无法交互**：需要输入的命令（确认提示等）会因 stdin 关闭而失败；
- **没有进程级沙箱**：命令能访问网络、能读写当前用户权限下的任何文件——
  这是"本地执行命令"的固有含义；介意的话把 `config.py` 的 `ENABLE_EXEC` 关掉；
- **超时是"整条命令"的**：长任务（训练、大批量构建）需要拆分，或写成脚本分段跑。
