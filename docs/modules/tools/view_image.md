# 工具：view_image（看图）

| 状态 | 最后更新 | 关联代码 | 代码基线 |
|---|---|---|---|
| Stable | 2026-10-24 | `tools/view_image.py` | `a647e30` |

> 所属：[工具系统总览](README.md)

## 1. 职责

读取工作区里的一张图片（PNG / JPEG / GIF / WebP），**让模型"看"到它**。
模型平时只能读文本；这个工具把图片递到它眼前。

典型用途：配合 [screenshot](screenshot.md) 做**自检闭环**——
生成页面 → 截图 → 看图发现问题 → 修 → 再截。

## 2. 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | 是 | 相对工作区的图片路径（如 `.screenshots/shot-120000.png`） |

## 3. ★ 实现机制：为什么图片要"绕道"附件槽

官方限制：**图片只能放在 user 消息里**（tool / system / assistant 消息带图会 400）。
而工具的结果天然走 `role=tool` 消息——直接返回图片是行不通的。

所以本工具的流程是：

```
run() 读文件 → base64 data URL → toolbox.attach({"image_for_model": ...})
        ↓（工具返回一句文字："已加载图片 xxx"）
engine 从附件槽取出图片 → 在 tool 消息之后**追加一条 user 消息**：
        [{"type":"text","text":"（这是工具 view_image 读到的图片：xxx）"},
         {"type": "image_url", "image_url": {"url": data-url}}]
        ↓
模型下一轮"看到"了这张图
```

配套的细节：图片的 base64 **不进事件日志**（`extra` 里被 pop 掉）、
**不进链路快照**（`_slim_message` 把 image_url 块替换成"（图片数据已省略）"）。

## 4. 错误路径

| 情况 | 返回 |
|---|---|
| 路径为空 / 越界（`../`） | `错误：…`（`safe_path` 拦截） |
| 文件不存在 / 是目录 | `错误：图片不存在 / 这不是一个文件` |
| 后缀不是图片格式 | `错误：不支持的图片格式…` |
| 超过 `MAX_IMAGE_MB`（默认 5MB） | `错误：图片太大…` |

## 5. 已知限制与坑

- **依赖视觉能力**：跟 `config.ENABLE_VISION` 一起开关；关掉后工具不注册；
- **子代理看不到图**：子代理消费事件流时不处理"附件图片"——
  子代理做文本调查没问题，看图的活留给主 agent；
- **图片进了上下文就一直在**：后续每轮请求都会带上这张图（每张约 400 token），
  嫌重就开新对话；
- 只支持常见位图格式；SVG 等矢量格式不支持（可先截图转 PNG）。
