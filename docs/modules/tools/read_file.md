# 工具：read_file（读文件）

| 状态 | 最后更新 | 关联代码 | 代码基线 |
|---|---|---|---|
| Stable | 2026-10-16 | `tools/read_file.py` | `515d604` |

> 所属：[工具系统总览](README.md)

## 1. 职责

读取工作区内的文本文件，**输出带行号**。两个设计点都学自 Pi 的 read 工具：

1. 可按行号范围分段读（大文件不用一口吞）；
2. 默认带行号——模型引用代码时能说"第 42 行"，
   写 `edit_file` 的 `old_text` 时也有据可查。

## 2. 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | 是 | 相对工作区的文件路径 |
| `offset` | integer | 否 | 从第几行开始读（**行号从 1 数起**），默认第 1 行 |
| `limit` | integer | 否 | 最多读多少行，默认读到文件结尾 |

## 3. 行为与输出

- 按 UTF-8 读取，`splitlines()` 切行；
- 行号格式右对齐 4 位：`  42 | print('hi')`；
- 输出头部带元信息：`文件：xxx（从第 N 行起，共 M 行）`；
- **截断保护**：单次返回最多 `MAX_CHARS = 8000` 字符（约 2000~4000 个汉字），
  超出部分截掉并附提示 `…（太长已截断。文件共 M 行，可以用 offset/limit 分段读）`
  ——防止把模型的上下文塞爆；
- offset 超出行数时返回 `（没有内容：文件共 M 行，你请求的是从第 N 行开始）`。

## 4. 错误路径

| 情况 | 返回 |
|---|---|
| 文件不存在 | `错误：文件不存在：xxx` |
| 路径是目录 | `错误：这不是一个文件：xxx` |
| 非 UTF-8 文本（如二进制） | `错误：xxx 不是文本文件（按 UTF-8 解码失败）` |
| 其他读取失败（权限等） | `错误：读取失败：…` |

## 5. 实现要点与坑

- **截断按字符数而非行数**：一行超长的文件（如压缩后的 JS）可能没几行
  就触发截断——提示语引导模型用 offset/limit 继续，但 offset 是**行**粒度，
  极长单行文件无解（已知限制）；
- **8000 字符是硬编码常量**（文件顶部 `MAX_CHARS`），调整直接改它；
- 读取的是文件**当时**的内容——若模型先 read 再等一轮后又 edit，
  中间文件可能已被改（edit_file 的唯一性校验就是防这个的兜底）。
