# 工具：edit_file（精确修改）

| 状态 | 最后更新 | 关联代码 | 代码基线 |
|---|---|---|---|
| Stable | 2026-10-16 | `tools/edit_file.py` | `515d604` |

> 所属：[工具系统总览](README.md)

## 1. 职责

对已有文件做"查找替换"式的**精确修改**（学自 Pi 的 edit 工具）——
在任何情况下都不要用 `write_file` 重新生成整个文件来"改几处"，
`edit_file` 才是正确姿势。

## 2. 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | 是 | 相对工作区的文件路径 |
| `old_text` | string | 是 | 要被替换的原文——**必须与文件内容完全一致，且在文件中恰好出现一次** |
| `new_text` | string | 是 | 替换后的新内容（可为空字符串 = 删除这一段） |

## 3. ★ 安全设计：唯一性校验（本工具最重要的地方）

替换前先数 `old_text` 在文件里的出现次数：

| 出现次数 | 结果 |
|---|---|
| **恰好 1 次** | 执行替换（`replace(..., 1)`） |
| **0 次** | 拒绝：`错误：在文件里没找到 old_text。请先用 read_file 看一遍真实内容，确保原文一字不差。` |
| **多次** | 拒绝：`错误：old_text 在文件里出现了 N 次，无法确定要改哪一处。请把 old_text 换成更长的一段（上下文多带几行）让它只出现一次。` |

**为什么这么设计**：模型不可能"改错地方"——比整文件重写的唯一性与
安全性高得多。被拒不是失败，而是给模型的信息："去重新看文件 / 带更多
上下文重试"。

## 4. 行为与输出

- 成功返回：`修改成功：xxx.py 里替换了 1 处内容。`；
- 替换会**保持文件其余部分一字不动**（这正是相较 write_file 的优势）。

## 5. 错误路径

| 情况 | 返回 |
|---|---|
| 文件不存在 / 不是文件 | `错误：文件不存在：xxx` / `错误：这不是一个文件：xxx` |
| 读取失败 | `错误：读取失败：…` |
| `old_text` 0 次 / 多次 | 见 §3（带重试指引） |
| 路径越界 | `safe_path` 抛 ValueError → `toolbox.call` 兜底转文本 |

## 6. 实现要点与坑

- **不要"顺手"放松唯一性**：0 次和多处都拒绝是核心安全机制，改它就等于
  打开"改错地方"的门；
- `old_text` 的**空白/换行必须一字不差**（模型经常在缩进上栽跟头——
  错误提示专门引导它先 `read_file`）；
- 一次调用只改一处；多处修改就多次调用（每处单独保证唯一）。
