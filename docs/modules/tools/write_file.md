# 工具：write_file（写文件）

| 状态 | 最后更新 | 关联代码 | 代码基线 |
|---|---|---|---|
| Stable | 2026-10-16 | `tools/write_file.py` | `515d604` |

> 所属：[工具系统总览](README.md)

## 1. 职责

创建新文件，或**整体覆盖**已有文件。
说明书里专门提醒模型："只修改文件中几处内容时，请改用 `edit_file`
（更安全）"——因为覆盖式写入容易"重新生成整个文件"时在别处翻车。

## 2. 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | 是 | 相对工作区的文件路径 |
| `content` | string | 是 | 要写入的**完整内容** |

## 3. 行为与输出

- 父目录不存在时**自动创建**（`mkdir(parents=True)`，比如写
  `abc/def.txt` 时 `abc` 还不存在也 OK）；
- UTF-8 写入；
- 返回区分"创建/覆盖"并附统计：
  `已创建文件 xxx.txt（12 行，340 字符）` / `已覆盖文件 …`。

## 4. 错误路径

| 情况 | 返回 |
|---|---|
| 路径越界 | `safe_path` 抛 ValueError → `toolbox.call` 兜底为 `错误：工具执行失败：路径越界：…` |
| 目录创建/写入失败（权限等） | 同上，异常被兜底转文本 |

## 5. 实现要点与坑

- **整份替换语义**：内容里没写到的部分就没了——这是"覆盖"的字面含义，
  没有"追加"或"部分更新"模式（部分更新用 `edit_file`）；
- **写入无预览、无确认**：模型在工作区内可以直接写（有意的自主性设计）；
  要加"写前审批"可以挂 `before_tool` 空槽（见 [toolbox](../toolbox/README.md) §4.3）；
- **空字符串 content 是合法的**：会写入一个空文件（不是错误）。
