# 插件：logger（对话日志）

| 状态 | 最后更新 | 关联代码 | 代码基线 |
|---|---|---|---|
| Stable | 2026-10-16 | `plugins/logger.py` | `515d604` |

> 所属：[插件系统总览](README.md)

## 1. 职责

**教学示例插件**：演示 `after_llm` 空槽的用法——每次 AI 回答后，
在服务端终端打印一行"用户问了什么、AI 答了什么"。

它是全项目最小的插件（20 行），写自己的第一个插件时照抄它最合适。

## 2. 行为

- 取 `ctx["messages"]` 的最后一条的 `content` 作为"问题"（截前 40 字符）；
- 取 `ctx["reply"]` 作为"回答"（截前 40 字符）；
- 打印两行：

  ```
  [对话] 用户问：帮我看看项目里有什么
  [对话] AI 答：我看到项目里有以下文件……
  ```

## 3. 实现要点与坑

- **只读不写**：after_llm 的语义是"记录类用途"——它拿得到完整回答，
  但**改不了已经流出去的内容**（流式架构的本质取舍）；
- **截断显示**：只打前 40 字符（终端日志保持清爽，不是存档）；
- **极端情况**：代码假设"最后一条消息带 content"——正常链路下
  （最后一条是用户的新消息）总是成立；万一不成立，产生的异常会被
  engine 的 after_llm 容错兜住（只打警告，不影响对话）；
- 子代理干活时也会触发本插件（子对话也算一次对话）——终端里看到
  "子代理的任务与结论"日志是预期行为，不是串台。
