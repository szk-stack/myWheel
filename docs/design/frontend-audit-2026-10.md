### AI Slop 判定：**PASS（通过）** ✅

对照全部 AI 反模式逐条检查：无紫蓝渐变、无霓虹、无毛玻璃、无渐变文字、
无英雄指标布局、无同质卡片网格。等宽字体（工具卡片内部）使用合理
（表达"原始输出"语义）。

**但要诚实地说**：这更像"还没来得及设计"而不是"设计得克制"——
底色 #f2f4f8 是冷灰蓝的默认感、主色 #4a7cff 是"没有主张的通用蓝"。
改造方向不是换皮，是**把"克制"变成有意识的表达**。

### 一句话总结

> 一个**功能反馈做得远超平均水平**（流式、工具过程、子代理全程可见）、
> 但**从未建立过设计层**（无 token、无焦点设计、无动效、状态保持不完整）的界面。
> 好消息：地基干净、语义正确，全部问题都有明确的修法；目标是把 10/20 提到 16+。

## 二、亮点（改造时不要破坏）

1. **过程可见性**（全项目最强的设计资产）：打字机、工具状态行、子代理
   "出动"文案、用量条——把 agent 的"黑盒干活"变成了可见的流水账；
2. **语义结构正确**：`aside / main / header / footer / ul` 用对了，
   `lang="zh-CN"` 有，大部分交互用了真 `<button>`；
3. **零外部资源**：两个本地 JS 库、系统字体、无图片——加载瞬发；
4. **错误文案人话化**："连不上后端服务，请确认 server.py 正在运行"
   ——直接可读可行动；
5. **色彩的语义方向正确**（蓝=主操作、紫=压缩/子代理系统、红=错误）
   ——只是没有收敛成系统。

## 三、问题清单（按优先级）

### P1 · 重大（改造第一批处理）

**1. 没有"停止生成"**
- **位置**：`sendMessage()` / 输入区（发送按钮发送中仅置灰）
- **影响**：长回答无法中断；误发只能干等（还持续消耗 token）；
  流式断网时用户无出口。聊天工具的标配能力缺失。
- **建议**：发送中把「发送」变为「停止」（`AbortController` 中断流读取，
  保留已生成内容）；停止后状态与记账保持一致
- **命令**：直接实现（功能补全）

**2. 键盘可达性三层缺口**（WCAG 2.1.1 / 2.4.7）
- **位置**：① `tool-card-head`、`compact-card-head`、`#contextMeter`
  是 `div` + click（不可聚焦）；② `msg-actions button`、`.conv-item button`
  为 `opacity: 0` 悬浮才显示——键盘 Tab 到时**看不见焦点**；③ 全站无统一的
  `:focus-visible` 样式
- **影响**：键盘用户无法展开工具卡片、不知道自己焦点在哪
- **建议**：① 换 `<button>` 或补 `role/tabindex/keydown`；② 增加
  `:focus-within` / `:focus-visible` 让按钮在键盘聚焦时可见；
  ③ 定义统一的焦点环 token
- **命令**：`/harden`

**3. 多处辅助文字对比度 < 4.5:1**（WCAG AA）
- **位置**：`.tool-line`（#999 on #f2f4f8 ≈ 2.6:1）、`#contextMeter`、
  `#workspaceTag`、`.conv-item button`（#888 系列 ≈ 3.2–3.5:1）
- **影响**：弱视/低质量屏幕下小字难以辨认
- **建议**：灰阶收进色板时把"辅助层"提升到 ≥4.5:1（如 #5f6368 档位）
- **命令**：`/colorize` + `/harden`

**4. 展开状态在重绘后丢失**
- **位置**：`renderMessages()` 全量重建（`chatBox.innerHTML = ""`）
- **影响**：工具卡片/子代理过程读到一半，发条消息全折叠回去；
  对"观察 agent 干活"这个核心用途直接干扰
- **建议**：渲染时按消息索引恢复 `open` 状态；或改为增量更新
- **命令**：`/harden`

**5. 发送失败会丢用户输入**
- **位置**：`sendMessage()` 的 `catch`（`conv.messages.pop()` 但输入框已清空）
- **影响**：网络抖动/后端未启动时，用户刚写的内容蒸发
- **建议**：catch 时把 `text` 恢复回输入框
- **命令**：`/harden`

**6. 设计 token 缺失**（工程地基，非用户可见）
- **位置**：全部 CSS——约 35+ 个硬编码色值、6 种圆角（4/6/8/10/14/999px）、
  6 级字号（12–18px）、间距无体系
- **影响**：阻塞所有主题化改造（换色板、调间距都是"处处改"）
- **建议**：`/extract` 一套变量：色板（暖中性 + 强调色）、字号阶梯、
  间距节奏、圆角/阴影 token
- **命令**：`/extract`

### P2 · 次要（第二批）

**7. 流式渲染 O(n²)**：每个 delta 对整段文本重跑 `marked + DOMPurify`
（`currentBubble.innerHTML = renderMarkdown(currentText)`）——几千字长回答
会累积卡顿。建议：rAF 节流 + 仅重渲染当前段。命令：`/optimize`

**8. 空状态无引导**：新对话只有一句欢迎语。这是给来访读者的"第一印象位"，
建议做成欢迎 + 2-3 个可点击示例任务。命令：`/onboard`

**9. 视觉系统不统一**：灰色深浅 6+ 档随意、圆角 6 种、间距靠手感——
在 token 地基上系统化。命令：`/arrange` + `/typeset`

**10. 弹层无 Esc 关闭**（`#contextPanel` / `#workspaceMenu` 只支持点外部收起）。
命令：`/harden`

**11. 触摸目标偏小**：会话操作按钮 ~21px、分支按钮 ~22px（标准 ≥44px）。
桌面为主可降级处理。命令：`/adapt`

**12. 进度条与动态内容无 ARIA**：`#contextBar` 建议
`role="progressbar" + aria-valuenow`；消息流可加 `aria-live`。
命令：`/harden`

### P3 · 打磨（收尾批）

- 动效全缺（一切瞬变：卡片展开、消息出现、hover 无过渡）——做成
  "状态变化动效 + 指数缓动"的一套（`/animate`）
- 记忆点缺席：可以有 1 处与「简 / 竹简」呼应的精致细节（`/delight`）
- 发送中按钮只有置灰，无进行态表达（`/animate`）
- `contextFill` 的 `width` 过渡可改 `transform: scaleX()`（性能规范，`/optimize`）

## 五、系统性发现

1. **"功能一层层长出来，从未有过设计层"**：所有问题同根——
   每个功能都在叠加新色值/新圆角/新交互惯例，没有统一收敛过。
2. **hover-only 的交互习惯**（学 Pi 的做法）在鼠标场景顺手，
   但代价是键盘/触摸/截图的完全不可见——需要"焦点即显示"的兜底。
3. **反馈哲学已经存在**（过程可见性极强），缺的是**操作级反馈**
   （按钮动作、保存成功、状态保持这类"小闭环"）。

## 六、推荐改造序列

按序推进，每批可独立验收：

1. **`/extract`** — 建立设计 token（色板/字号/间距/圆角/阴影，暖中性方向）
2. **`/harden`** — 清 P1 缺陷：停止生成、键盘可达、对比度、状态保持、错误恢复
3. **`/colorize` + `/typeset`** — 在 token 上施展"纸墨"调性（主色降噪、
   排版节奏、层级）
4. **`/animate`** — 状态变化动效（卡片展开、消息进入、流式光标）
5. **`/onboard` + `/delight`** — 空状态引导 + 一处记忆点
6. **`/polish`** — 上线前一致性终检；然后重跑 `/audit` + `/critique` 对比分数
