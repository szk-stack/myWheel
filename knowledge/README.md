# knowledge/ —— 你的知识库原料仓

这个目录里的 `.md` 和 `.txt` 文件会被 `rag.py` 扫进知识库索引，模型可以用
`search_kb` 工具搜到它们。`docs/` 目录也会被一起索引（项目自己的技术文档）。

## 放什么

按主题分文件，一个文件讲一件事。文件名即标题，检索时能看到来源路径。

```
knowledge/
  rag/                 ← RAG 相关（面试、论文笔记）
    面试考点.md
    切分策略.md
  agent/               ← Agent 相关（架构、工具调用、记忆）
    上下文压缩.md
  读书笔记/
    某某书第3章.md
```

## 写的时候注意（这几条直接决定检索效果）

1. **标题要写清楚**。检索时会带上标题路径，标题写得含糊，这段就很难被搜到。
   好："## 小块检索 + 大块返回"，坏："## 方案二"。

2. **一段只讲一件事**。800 字左右自然分段。不要一个文件写三万字的流水账。

3. **术语要写全**。BM25 就是 BM25，别一会儿写"BM25"一会儿写"那个打分算法"。
   现在的检索是关键词匹配，不懂同义词（这是第一版的已知短板）。

4. **记下"为什么"**。你自己的思考、踩的坑、判断依据，比抄来的定义值钱得多。
   这些内容在别处搜不到，是知识库真正的护城河。

## 建索引

改完文件后要重新建索引才会生效：

```bash
python rag.py build
```

试试搜一下：

```bash
python rag.py search 空槽机制
python rag.py stats
```
