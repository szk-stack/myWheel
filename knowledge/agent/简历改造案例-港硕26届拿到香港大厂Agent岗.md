## 案例概况

- 背景：**港硕，26 届**，此前求职不顺利，自己包装简历大半年，还买过几个知识星球，越改越不知道该怎么弄。
- 6 月和 UP 主开了一次会，此前校招面了几家都没过。
- 结果：**拿到香港一家全球化大厂（AI Agent 相关岗位），薪资 25~26K**。

这条视频的价值不在"求职故事"，而在**简历被怎么诊断、按什么逻辑改**——下面四条改法可以照搬到自己的简历。

## 诊断：第一眼看的是「技术栈账」不对

- 他曾内推去面**网易 AI 应用开发，一面挂**。
- 一面挂了 **16 个问题，全是 Java 八股**。
- 原因：**简历上两个 Agent 项目，技术栈全写的 Java**。

这是典型的「技术栈与岗位错位」：投的是 AI 应用开发（Agent）岗，简历通篇 Java，面试官自然顺着简历问 Java 八股，而候选人准备的是 Agent 内容，双方对不上，一面必挂。

**判断口径**：简历写的技术栈，决定了面试官问什么。想面 Agent 岗，简历主项目的技术栈就得是 Agent 生态的那套，不能是 Java。

## 四处具体改法

### 改法一：主项目技术栈从 Java 换成 Python

主项目是简历的重心，也是面试追问的落点。原来两个 Agent 项目都写 Java，改成 Python 之后，面试官追问的方向才会落到 Agent 本身。

### 改法二：个人项目 → 企业交付经验

- 原状：写的是个人项目，底子是一个开源仓库（拿开源改的）。
- 改后：包装成**企业级交付经验**。

关键在于这不是纯编：他做的时候**确实是和客户合作做的**，有真实交付场景，只是简历上没这么表述。所以这一步是**把已有的真实经历按企业交付的口径重新表述**，而不是无中生有。

（这是简历改造里最值钱的一条：先找经历里被忽略的"真实成色"，再改表述，而不是硬造。）

### 改法三：所有数字补上口径

原文是"数字上我们全补上口径"。简历上的量化指标（QPS、准确率、提效百分比、数据量）光有数字不够，**必须能说清这个数字是怎么算出来的**——统计口径说不清，面试官一追问就露。

### 改法四：架构描述改成 supervisor 等多 agent 术语

把项目里的架构描述换成 **supervisor（多 agent 主管型架构）** 这类业界通用叫法。目的是让面试官一眼对上他熟悉的技术词汇，而不是自己去翻译你的自造说法。

## 行业判断（候选人自己的体感，UP 主转述）

- **很多公司已经不自己造框架了**，都是拿现有框架去解决自动化的问题。
- 他现在在公司做的也是同样的事。

对求职的启示：简历和面试里讲"我设计了一套 Agent 框架"的说服力，可能不如"我用成熟框架把某个自动化流程跑通了"——后者更贴近企业实际在干的事。

## 求职策略：26 届的市场现实

- 他投 27 届岗位时发现：**很多公司一看是 26 届就直接拒**（26 届被当成"过期批次"）。
- 于是**转投香港**，结果投上去，进了一家大厂。
- 他反馈：**内地 985 也很多没 offer，很卷**——所以不是单纯学历或能力问题，是在卷同一个池子。

策略上值得记的一条：**校招批次不对时，换地域池子比在同一个池子里硬卷更有效。**

```

  2. 个人项目/开源改 → 企业交付经验（本来就有客户合作，只是没写出来）
  3. 数字全部补上统计口径
  4. 架构表述改用 supervisor 等通用术语

```
